4. What Do These Features Mean?

  • Amount — how much the transaction was for. Fraud in this dataset tends to involve larger amounts.
  • Hour of day — when the transaction happened. Late-night/very-early-morning hours are more associated with fraud here.
  • Distance from home — how far the transaction location is from the cardholder's home. Fraud tends to happen further away.
  • Foreign transaction — whether it happened in a different country than the cardholder's home country.
  • Online / card-not-present — whether it was an online purchase rather than a swipe/tap in person. Card-not-present fraud is a real, common fraud category.

This is a small synthetic dataset built to loosely resemble these real-world patterns — it's for learning the mechanics of a fraud-detection pipeline, not a production-grade fraud model.

5. How Does the Threshold Affect Results?

The model doesn't just output "Fraud" or "Not Fraud" — it outputs a probability between 0 and 1. The threshold is the cutoff we use to turn that probability into a final decision: if probability ≥ threshold, we call it fraud.

  • Lower threshold (e.g. 0.1): The model flags more transactions as fraud. This increases recall (catches more real fraud) but also increases false positives — more genuine transactions get wrongly blocked, which lowers precision.
  • Higher threshold (e.g. 0.9): The model only flags transactions it's very confident about. This increases precision (fewer genuine transactions wrongly flagged) but increases false negatives — some real fraud slips through undetected, lowering recall.

Move the slider above to see the exact trade-off for this dataset.

In real fraud detection, banks usually prefer a lower threshold because missing real fraud (false negative) is often more costly than a customer's card being wrongly declined for a moment (false positive).
